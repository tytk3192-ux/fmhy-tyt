版本 1.0｜2026年9月30日｜时间统一显示为北京时间 Asia/Shanghai

历史资源应作为寻找替代方案的线索。推荐前必须核验当前状态，分别记录历史事件时间与实际验证时间，并说明测试覆盖到哪一层。本方案用于个人 FMHY 仓库与 agent 检索流程，供后续分析和修订。

### 二 历史保存与检索架构

建议用 upstream-wiki 分支保存源历史，main 分支存放个人文档与整理结果。迁移时完整克隆源 Wiki，再推送到专用分支；首次迁移应核对源提交、历史数量与文件树，后续只推进已验证的更新。

如本地推送缺少身份验证，可评估在 GitHub Actions 中使用具备 contents 写权限的 GITHUB_TOKEN 执行迁移。须先验证工作流写入权限、Actions 设置和分支限制。此路线尚未在本仓库执行。

在历史之上生成链接索引，关联出现、移除和重新收录事件。优先检索当前目录；不足时检索历史索引，再查看提交差异。曾经删除只说明记录发生变化，不能直接推断站点价值或删除动机。

## 资源记录字段与时间规则

### 三 每条资源保留可追溯字段

| 字段 | 记录要求 |
| --- | --- |
| 资源身份 | 记录名称、原始 URL、分类、源文件路径与证据提交。域名相同不等于项目身份相同。 |
| 首次收录时间 | 现存历史中首次观察到的收录事件；注明提交 SHA，不解释为网站成立时间。 |
| 最近变更时间 | 最近一次涉及该资源的改动；文件整体更新时间不能替代资源更新时间。 |
| 删除与重新收录 | 保留事件序列与提交，区分移除、改名、迁移和重新出现。删除原因无明确依据时标未知。 |
| 项目更新时间 | 记录官方版本、公告或提交日期及来源。无可确认来源时留空。 |
| 最近验证时间 | 记录实际执行时间、验证层级、方法与环境；未检查就留空，禁止填文档创建时间。 |
| 验证结果 | 保存状态、具体功能、限制、证据、失败原因和下一步核验事项。 |

### 四 时间与证据不能混用

事件时间保留来源原值与时区，显示时转换为北京时间。提交时间仅证明记录在该时点发生变化；作者时间和提交者时间有差异时都保留。精度只有日期的来源只显示日期，不能补造时分。

空值代表未查明，不使用当天日期填补。历史记录未再出现某链接，不能据此证明它一直失效。源历史已被改写或截断时，首次收录应标为可见历史中的首次观察。

原始 URL 保留不变，可另存规范化 URL 用于去重。只做可解释的规范化，不盲目移除查询参数或合并不同服务路径。每次验证新增一条记录，最新状态引用最新相关记录，不覆盖过往证据。

## 可用性验证与失败处理

### 五 验证结论受测试范围约束

| 层级 | 检查对象 | 可报告结论 |
| --- | --- | --- |
| 页面访问 | 连接、响应、跳转和实际页面内容 | 页面可访问；仅 HTTP 200 不足以证明服务正常。 |
| 服务状态 | 官方停运通知、新域名、登录及地区条件 | 服务状态与使用条件；记录证据来源。 |
| 核心功能 | 与任务相关的搜索、下载或其他操作 | 仅报告实际测试成功的功能及范围。 |
| 需求适配 | 设备、系统版本、成本与任务目标 | 说明适用条件；未在用户设备测试时不保证兼容。 |

测试默认采用只读或低影响操作。需要登录、付费、安装或产生外部影响时，先利用已有授权判断可执行范围；不能执行的测试标未验证，并说明具体阻碍。不得将他人的使用报告当作本次实际测试。

### 六 一次失败先分类再下结论

连接超时、DNS 失败、403、429、验证码或登录墙分别记录。先检查是否有官方停运或迁移信息，再选择不同时间、允许的访问渠道或官方替代入口复核。重复相同请求没有新证据时停止，保留暂时无法确认。

| 状态 | 判定依据 |
| --- | --- |
| 已验证可用 | 本次目标功能完成，记录时间与环境。 |
| 部分可用或有条件 | 部分功能完成，或存在明确登录、地域、设备等条件。 |
| 暂时无法确认 | 证据不足、访问受阻或未覆盖核心功能。 |
| 已停运或功能失效 | 有官方停运证据，或可复现的核心功能故障；标注具体范围。 |
| 疑似域名易主 | 跳转或内容与原项目身份明显不符，另行标记并停止沿用旧评价。 |

## 推荐流程与实施验收

### 七 每次推荐重新核验相关功能

先将用户需求写成可验证目标，再从当前目录筛选；候选不足时查询历史。对入选候选核验身份、服务状态及目标功能，记录实际时间与证据，再按适配程度推荐。不能复查的条目降为历史线索，显示上次验证日期。

缓存结果用于安排复查，不能替代本次检查。暂不设置未经验证的统一有效天数；登录条件、版本、域名、服务公告或用户需求发生变化时立即重新检查。验证结果只描述指定时点和环境，不承诺未来持续可用。

### 八 推荐格式示例

以下为格式示例，资源和日期均为示例数据，不代表已完成现场验证。

资源 A｜历史候选。首次收录：2023-06-12；移除：2025-11-03，原因未知。最近验证：2026-09-30 09:30 北京时间。状态：页面可访问；核心功能需要登录，未验证。环境：云端浏览器，未测试用户安卓设备。判断：继续调查，暂不足以推荐为可用方案。

### 九 后续实施与验收标准

第一阶段完成规范文档入库。第二阶段迁移源历史并核对完整性。第三阶段生成历史事件索引，以少量资源人工校核首次出现、删除、改址和重新收录。第四阶段开展实际功能验证，再决定是否启用定时同步。

验收要求：每条推荐都能回答信息来自什么时候、实际检查了什么、哪些条件未验证；每个历史事件能追溯到提交与文件；空值、未知和访问失败不会被转换成确定结论；历史分支、索引与验证记录的完成状态分别报告。

### 十 分析时重点审阅的问题

检查时间字段是否足以区分历史与现状，验证分级是否贴合实际用途，失败判定是否过早，以及输出是否便于快速选择。先用一个具体资源案例验收，再根据误判与遗漏修订版本。
